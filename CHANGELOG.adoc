= changelog

== 2026-09-01 - macOS arm64 release artifact (0.1.2)

* v0.1.1 shipped without `notorious-macos-arm64.zip`: the release workflow ran before the glfw-d Cocoa fork landed and macOS was still `continue-on-error`.
* Release matrix now checks out `dlang-supplemental/glfw-d` and treats macOS arm64 as a required slice (Windows arm64 remains soft-fail).
* Details: link:changelog-details/2026-09-01 - macos-release-artifact.adoc[2026-09-01 - macOS release artifact]

== 2026-08-30 - Ship windowed UI in releases (0.1.1)

* v0.1.0 installers accidentally shipped the headless CI binary (`-c application`): console flash, one SoftwareBackend frame, no GLFW UI.
* Releases now build `-c windowed` (Rust toolchain for vello-d), and CI compiles windowed on every push. Windows GUI subsystem avoids a console on launch.
* Fixed dew/dui version bleed: dui no longer defines `DewHeadless` (that forced Vello stubs while compiling the host). Linux uses X11/Wayland attach like dew's vello-window demo.
* macOS windowed build uses `dlang-supplemental/glfw-d` (fork of dkorpel/glfw-d) with Cocoa/NSGL support; CI no longer soft-fails macOS.
* Details: link:changelog-details/2026-08-30 - ship-windowed-release.adoc[2026-08-30 - Ship windowed release]

== 2026-08-30 - Release installers as top-level assets

* Inno Setup still built for v0.1.0, but the pack step nested `*-setup.exe` inside the Windows zip. Releases now publish setup executables next to the portable archives (arch in the filename).
* Details: link:changelog-details/2026-08-30 - release-installer-assets.adoc[2026-08-30 - Release installer assets]

== 2026-08-30 - Plain / Doc / Canvas + OCIF direction

* Mode strip target: **Plain | Doc | Canvas**. Doc = CentrMark; Canvas = OCIF (SVG export). No bottom status bar — mode subbars. See [`AGENTS.md`](AGENTS.md).

== 2026-08-30 - Drop notor launch alias

* Launch set is now `note` (primary), `noto` (when `note` conflicts), and `notorious`. Removed the `notor` shim / App Paths entry.

== 2026-08-30 - CLI PATH shims (note / noto / notorious)

* Installer installs same-bytes shims, App Paths for Win+R, and an optional user-PATH entry so terminals can run `note` / `noto` / `notorious`.
* Details: link:changelog-details/2026-08-30 - cli-path-shims.adoc[2026-08-30 - CLI PATH shims]

== 2026-08-30 - Copy as… format registry

* Ctrl+Shift+C / **Copy as…** opens a format picker (plain, Markdown, CentrMark, RST, AsciiDoc, HTML, RTF).
* First-party D format modules under `source/notorious/formats/` — no in-app extension store.
* “Open as code” + side navigator/compare/preview stubs for source editing.
* Details: link:changelog-details/2026-08-30 - copy-as-formats.adoc[2026-08-30 - Copy as formats]

== 2026-08-29 - Win+R aliases (noto / notor / notorious)

* Installer registers App Paths for `noto`, `notor`, and `notorious` (optional task, on by default) so Win+R launches the app without PATH changes.
* Details: link:changelog-details/2026-08-29 - winr-app-paths.adoc[2026-08-29 - Win+R aliases]


== 2026-08-29 - Release target pattern desktop/2026

* Release matrix includes `windows-arm64` and `linux-arm64` (house `desktop` pattern) alongside existing x64 + macOS arm64.

* Catalog with list/grid views and search; per-note sticky background colors.
* Text ↔ Canvas mode with Undo/Redo; reverse locked once diagram shapes exist.
* Clipboard: Ctrl+C HTML (no document background), Ctrl+Shift+C Markdown.
* UTF-8 + LF defaults; About / Help / redacted debug dump.
* CI matrix + Inno Setup installer script; depends on dui 0.1.3 / dew 0.1.6.

Details: link:changelog-details/2026-08-29 - initial release.adoc[2026-08-29 - initial release]
